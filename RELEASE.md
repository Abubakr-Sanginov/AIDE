# Как выпустить новую версию

Обновление в приложении работает так: AIDE раз в сутки (и по кнопке «Проверить обновления») читает
`latest.json` с `https://github.com/Abubakr-Sanginov/AIDE/releases/latest/download/latest.json`,
сверяет версию и подпись, скачивает установщик и ставит его. Значит для обновления нужен
**опубликованный релиз с более высокой версией**.

## Шаги

1. Поднять версию в четырёх файлах (она должна совпадать везде):
   - `package.json`
   - `src-tauri/Cargo.toml`
   - `src-tauri/tauri.conf.json`
   - `src-tauri/Cargo.lock` (поле `version` у пакета `tauri-app`)

2. Закоммитить и запушить в `main`.

3. Поставить тег с тем же номером и запушить его:

   ```bash
   git tag -a v0.2.4 -m "AIDE 0.2.4"
   git push origin v0.2.4
   ```

4. GitHub Actions (`.github/workflows/release.yml`) соберёт установщики, подпишет их и **опубликует**
   релиз. Через ~10–15 минут `releases/latest/download/latest.json` уже отдаёт новую версию, и
   приложение видит обновление.

5. Положить новый установщик на сайт: скачать `AIDE_<версия>_x64-setup.exe` из релиза в
   `site/downloads/`, удалить старый, затем `cd site && npm run build:vercel` и деплой.
   Кнопка на сайте ссылается на стабильное имя `/downloads/AIDE-latest-x64-setup.exe` —
   сборка сама берёт самый свежий файл из `site/downloads/`, поэтому ссылку менять не нужно.

## Подпись обновлений

- Приватный ключ: `%USERPROFILE%\.tauri\aide-updater.key` (пароль пустой). **В репозиторий он не попадает.**
  Держите резервную копию: без него нельзя выпустить обновление, которое примет установленное приложение.
- Публичный ключ лежит в `src-tauri/tauri.conf.json` → `plugins.updater.pubkey`.
- На GitHub ключ заведён секретом `TAURI_SIGNING_PRIVATE_KEY` (Settings → Secrets → Actions).
  Приватный ключ в секреты можно заливать так: `gh secret set TAURI_SIGNING_PRIVATE_KEY < путь\к\aide-updater.key`.
- Если ключ сменить, `pubkey` в конфиге надо обновить и выпустить версию — иначе старые установки
  откажутся принимать обновления.

## Если релиз собрался, но не виден приложению

- Релиз остался черновиком → опубликовать: `gh release edit v0.2.3 --draft=false`.
- Версия в `latest.json` не выше установленной → поднять версию и выпустить заново.
- Подпись сделана другим ключом → key id в подписи не совпадёт с `pubkey`. Проверить можно так:
  распаковать base64 из `pubkey` и из поля `signature` в `latest.json`, сравнить байты 2–10.
